# Background worker operations

`issue-orchestrator run --once` is the worker interface and remains usable directly; no service installation is required. It processes at most one active job. SQLite's process-wide mutation guard and unique active claim serialize simultaneous timer/container starts. SIGTERM/SIGINT aborts the active OpenCode process group, waits for cleanup, and exits 143/130. The durable issue claim, worktree, workflow checkpoint and session remain for the next invocation; an interrupted session is not a failed or terminal workflow. A queue claim intentionally remains held for exact resumption; the agent execution and process mutation leases are released on normal signal cleanup. SIGKILL cannot run cleanup; stale process leases are reclaimed and recovery checks durable branch/PR/evidence state before continuing.

## launchd / systemd

From the checked-out repository, run `node dist/cli.js service install --print`. This prints templates only: it does not read config, write files, call launchctl/systemctl, use sudo, or elevate. The template uses the current absolute Node and CLI paths and current repository as working directory. Save the printed plist under `~/Library/LaunchAgents` on macOS or both units under `~/.config/systemd/user` on Linux, then follow the exact commands printed. These are user-level services; do not install them as root. The Linux timer runs after boot and every five minutes; launchd runs at load and every five minutes. Ensure the user's login environment exposes the required provider CLIs/configuration.

## Docker

`docker compose up -d --build` builds the CLI from source (no host `pnpm build` needed) and runs a paced worker loop (one run, then a five-minute sleep) with `restart: unless-stopped`. The container runs as UID 1000, the non-root `node` user. The current repository is mounted read/write at `/workspace`, the worker changes there before every run, and it must be writable by UID 1000 because jobs create worktrees and push branches. Set `ISSUE_ORCHESTRATOR_INTERVAL_SECONDS` to an integer from 60 through 999999; invalid or shorter intervals make the worker exit rather than hot-loop. Keep the named `orchestrator-home` volume: it stores the SQLite queue and durable recovery artifacts. Supply a private `config.jsonc`, OpenCode config, OpenCode data/auth directory (including `auth.json`), and GitHub CLI credential directory via read-only mounts; never put credentials in the image or compose file. Set `OPENCODE_CONFIG`, `OPENCODE_DATA_DIR`, and `GH_CONFIG_DIR` to their host paths. The image itself does not mount a Docker socket: if configured Docker-backed DoD gates need one, explicitly add a socket bind mount and a vetted Docker CLI in `runtime-bin/`. This grants powerful host control; without it, those gates fail closed. Do not mount the host Docker socket by default.

The image bundles `git` but not `gh`, `opencode`, or Docker CLI; put vetted compatible executables in `runtime-bin/` (mounted read-only and prepended to PATH) or build a locally controlled derivative. Provider credentials in mounted files are available to the worker and agent; scope them narrowly. On shutdown, allow the worker to finish its current safe step and clean up the OpenCode process group, then restart normally. SIGKILL recovery is fail-closed if stored branch, pull request, or evidence identity cannot be verified. The optional standalone daemon is deferred.

Platform gates: launchd templates are validated by macOS CI; Linux units are checked in Linux CI/container. This package does not install service files automatically.
